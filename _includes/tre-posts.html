{%- comment -%} `tre posts/` — the homepage index. tre (dduan/tre), not GNU tree. Checked against the source rather than guessed, because the two differ in exactly the place this include ends: * prefixes are identical — "├── ", "└── ", "│ " and four spaces, from diagram_formatting.rs, so the guides below are the real strings; * the root prints as the literal argument with an empty prefix, which is why the first line is `posts/` and not `posts`; * tre prints NO trailing summary. GNU tree's "N directories, M files" was here and is gone — src/output.rs emits entry lines and nothing else. * tre takes exactly ONE path (`pub path: String` in src/cli.rs, default "."). GNU tree takes many. `tre posts/ drafts/` was here and is not a thing tre would accept, so drafts are a second invocation with their own prompt — see tre-drafts.html. ONE DELIBERATE DEPARTURE: directory names carry a trailing slash. tre has no -F/--classify — the whole flag set is -a -s -d -e -j -l -E -c -p — and its own tests show a directory entry named "b", no slash. It reads better with one and it is an author's call, so it is here, in the markup rather than in a ::after, so that a copied row still says `writeup/`. Each row carries its COMPLETE prefix rather than relying on nesting, which is what tre itself prints and what keeps a row intact when it is copied on its own. The guides are aria-hidden: the shape is a picture of a hierarchy the nested lists already state, and each row's link carries a full label. Box Drawing is 100% covered by the shipped Maple Mono — verified against the woff2 — so these are the real characters, not a CSS imitation. THE HIERARCHY IS THE SITE'S TAXONOMY, NOT THE SOURCE TREE. _posts/ is flat on disk; Jekyll requires it. Category and year are the two axes the site already indexes by (/categories/:name/ exists and is linked from here), so this is the directory layout the taxonomy describes rather than a claim about what ls would show. The alternative — a flat list — spent the depth on nothing and left no room for the tags. The leaf date is MM-DD because the year directly above it is the year. The full date is in the row's aria-label and in , so nothing is lost to a reader who cannot see the parent line. posts/ └── writeup/ └── 2022/ └── 07-15 madcore [pwn binexp googlectf] {%- endcomment -%} {%- comment -%} THE INDEX IS THE RECENT ONES, NOT ALL OF THEM. /archives/ lists every post already; two pages listing the same set with this one carrying strictly more detail was the same redundancy `choose-tree X` was killed for. So the front page is the newest `limit` and says how many it is not showing, and the archive is the complete record. Each has a job. site.posts is newest-first, so slicing from 0 takes the most recent without a sort. Below the limit — which is where this site is today — nothing changes: no row is hidden and no overflow line is drawn. limit how many posts to show.
