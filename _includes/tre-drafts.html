{%- comment -%} `tre drafts/` — the second invocation, rendered only when there are drafts. Rows come from _plugins/drafts.rb: the front matter of every file in _drafts/, merged with any hand-written rows in _data/drafts.yml. Writing a draft is putting a file in _drafts/; nothing else has to be told about it. A SEPARATE COMMAND, not a second root under the first. tre takes exactly one path — `pub path: String` with default "." in src/cli.rs — so `tre posts/ drafts/` is a line tre would reject. GNU tree accepts many paths and would have printed two roots under one command; tre does not, so this is two prompts, which is also what running it twice actually looks like. Flat, unlike posts/, and that is not an inconsistency: _drafts/ really is flat — Jekyll does not read subdirectories of it — and a draft has no published taxonomy to file itself under yet. So there are no directories here and nothing takes the trailing slash the posts tree gives them. Not links: a draft has no URL to go to. The mode bits carry the state the way they did in the `ls -la` this replaced — `-rw-------` is the file being unreadable by anyone but its owner, which is what an unpublished post is. drafts/ └── 2026-08-14 writeup some CTF 2026 — heap note -rw------- {%- endcomment -%}
